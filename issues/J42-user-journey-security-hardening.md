## FINAL VERDICT AND TODO:

**Verdict:** The original findings are mostly correct, but the original fix for envelope trust (only "reject envelopes with no `run_id`") does **not** close the main hole. All roles post as **one shared bot login** (`contracts/src/atobar_contracts/constants.py:59-65`), and a `run_id` is printed publicly in every envelope. So a prompt-injected **developer** sandbox can post a `flow-verdict: approved` that reuses an old evaluator `run_id`, and can create a green `flow/eval` check with its own token. That is self-approval, and self-merge under `auto_merge` (UJ-09). Design principle for this issue: **assume the sandbox is compromised and make stolen credentials worth little.** Do this with server-side checks (one envelope per run, role checks per endpoint, role-scoped GitHub tokens), not with more sandbox scrubbing.

**TODO (in order):**
1. [x] **WP-1 — Envelope authenticity (UJ-09, UJ-03):** each `run_id` may produce exactly one envelope, bound to its dispatched `head_sha` and its GitHub comment id. Reject envelopes with no `run_id`. Re-fetch comment bodies from GitHub instead of trusting the `/v1/events` payload.
2. [x] **WP-2 — Role-scoped GitHub tokens + role checks on the server (UJ-01, UJ-10):** the token's permissions come from the run credential's stored `role`. The wiki write endpoint accepts `onboarder` only. Remove the 404 fallback to the factory installation.
3. [x] **WP-3 — Loop-epoch marker integrity (UJ-02):** only honour the marker when the bot posted it **and** the comment starts with it.
4. [x] **WP-4 — Untrusted artifact bounds (UJ-06, UJ-07):** cap the metric artifact size before downloading and before unzipping. Reject newlines and `${{` in compiled metric commands.
5. [x] **WP-5 — No hard-coded fallback secrets (UJ-05):** use signing keys only when they are configured; otherwise disable the feature (503).
6. [x] **WP-6 (optional, low value) — Send `X-Instance-ID` (UJ-04):** cheap and consistent, but it is **not** a security control. Never count it as one.
7. [x] Moved out: **UJ-08** (session repo cap, uncached `llm-models`). This is a UX/performance bug, not a security issue; file it as a normal backlog issue.

## Part 3 — Edge Cases Audit

| Detail | Concurrency / Race | Partial Failure / Retry Idempotency | Pagination / Bounds / Truncation | Auth / Trust Boundary |
| :--- | :--- | :--- | :--- | :--- |
| **Envelope claim (`envelope_comment_id`)** | Webhook and `turn-complete` can arrive in either order for the same comment. The `= :cid` branch makes the second one a no-op, not a rejection. | A GitHub edit of the same comment (`issue_comment.edited`) is not ingested, so it can't swap the body after the claim. A redelivered webhook is already deduped by `comment:{pr}:{id}`. | `get_comments` must page past 100 comments on long PRs, or the re-fetch misses the comment → event ignored (safe, but the loop stalls). Add pagination, or fetch by id. | Forging now needs a **live, unclaimed** evaluator credential, which only exists inside an evaluator VM. Pair with J43 WP-2 (no warm handover into evaluator/arbitrator), or a developer-tampered VM *becomes* the evaluator VM. |
| **`head_sha` binding** | The developer pushes a new commit while the evaluator is running: the verdict's `head_sha` ≠ the PR head. The state machine already treats that as stale; the credential check must not *also* turn it into an error that halts the loop. | Legacy credentials (null `head_sha`) skip the check until they expire. | Plan envelopes have no commit; skip the check for `role == planner`. | Stops an old approval being replayed onto a new commit. |
| **Role-scoped tokens** | Concurrent developer/evaluator mints for the same repo must not share a cache entry. The key is `(repo, role)`. | If minting the engine read token fails, leave out `engine_token` (as today) without poisoning the repo cache. | Intersect with the installation's permissions. If the App lacks `checks: write`, the evaluator's `flow/eval` creation fails loudly, not silently. | Role comes from the DB record, never from the request body or headers. |
| **Workflow-path guard (developer)** | — | If *every* changed file is under `.github/workflows/`, push nothing and post an ack that explains why (no empty PR). | Match `.github/workflows/**` after normalising case and `./`. | Prevents developer → CI → `id-token` escalation in tenant repos. |
| **Epoch marker helper** | — | Older bot markers already in comment history start with the marker (verified writers), so behaviour doesn't change for legitimate resets. | Leading whitespace/BOM: use `lstrip()`. | A human quoting a bot comment (`> <!-- flow:loop-epoch -->`) no longer resets the loop. |
| **Metric artifact caps** | Stateless per request. | Over-cap → 422 with a clear reason in the metric PR check summary. Never retry-loop on it. | `size_in_bytes` missing from the listing → fall back to the streamed cap. | One tenant can no longer OOM the shared engine. |
| **Metric `${{` rejection** | — | Existing approved metrics that contain `${{` must be re-validated on the next manifest load and flagged, not silently dropped. | — | Closes Actions expression injection in compiled metrics. |
| **Signing-key fail-closed** | — | `refresh.sh` (J43) refuses to write an empty key, so 503 only appears on a broken deploy, never mid-flight. | — | No forgery with public defaults. |
